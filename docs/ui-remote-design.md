# UI 设计：远程与手机端（2026-11-22 设计稿）

> 状态：**设计稿，未实现**。配套 [remote-access.md](remote-access.md)（连接方案）。
> 纪律：只改投影层；不引组件库、不引状态库；动效只允许事件驱动。

## 一、设计问题

远程把两件事带进了界面，而现在的界面都没有位置：

1. **同一台机器可以有多个入口**（本机 pipe、SSH 远端、relay），它们指向同一批会话。
   现在 `Status` 只有一层 `reachable` 布尔，说不清"谁连不上"。
2. **手机是另一种形状**。它不是缩小版的桌面：屏幕窄、触摸、会断、会被系统杀。
   直接把桌面窗口按比例缩小，会把最需要的东西（"谁在等我拍板"）挤到看不见。

本文给出两件东西：桌面侧的**机器维度**扩展，手机侧的**独立信息架构**。

## 二、桌面：给舰队加一层"机器"

### 2.1 现状与缺口

舰队卡片现在显示：`session-id`、lifecycle badge、`mode` chip、目录 chip、command、
`unreachable` badge（`gui/src/components/FleetList.tsx`）。会话多了之后，
用户无法回答"这条会话在哪台机器上"——而这在远程之后是第一个问题。

### 2.2 方案：机器分段 + 每段自己的状态

舰队列表按机器分组，每段一个头，**不引入新的导航层级**：

```
┌ 本机 · 3 会话 ────────────────────┐
│ ● blocked  sess-a   acp   ...     │
│ ● working  sess-b   acp   ...     │
└───────────────────────────────────┘
┌ build-01 · SSH · 2 会话 ──── 延迟 12ms ┐
│ ● done     sess-c   pty   ...      │
│ ◌ unknown  sess-d   acp   ...      │
└────────────────────────────────────┘
```

三条规则：

- **机器头是分隔，不是可折叠面板。** 折叠会藏住 `blocked`，与"等你拍板的恒在最上"
  直接冲突。分段之后**全局排序不变**：`blocked(0) < done(1) < unknown(2) <
  working(3) < idle(4)` 仍然跨机器生效，机器只是视觉分组。
- **机器状态与会话状态分开报。** 机器头只显示四种：`live`（绿点）、
  `degraded`（琥珀点，**不转圈**——它已经连上了，只是某条转发坏了）、
  `reconnecting`（琥珀点 + 转圈，转圈只在真重连时动）、`offline`（红点，
  且该段会话一律显示 `unknown`，不显示上次的 `done`）。
- **离线机器的会话不删。** 保留最后已知状态并打 `stale` 标记，点击时尝试重连；
  删除是用户动作。

### 2.3 新的连接状态投影（纯函数，可测）

`store.ts` 现有 `StatusEntry.reachable: boolean` 拆成六值，保持向后兼容。
**2026-11-22 修订**：上一稿是 `live | stale | lost` 三值，与内核的六态不符——
三值里没有位置放 `degraded`（连上了但转发没挂上），而那正是用户最常撞到的
"连着呢怎么打不开"。

```ts
export type Link =
  | "idle"        // 还没开始连
  | "connecting"  // 首次连接中
  | "live"        // 心跳在阈值内
  | "degraded"    // 连上了，但至少一条转发/会话不可达；必须带上是哪一条
  | "reconnecting"// 掉线后正在退避重连
  | "stopped";    // 主动关闭或重连预算耗尽
```

- `stale` 不再是状态值，而是一个**正交标记**：`live` 但超过一个心跳周期没有新帧时
  打上它，UI 说"正在确认"。它不改变 `Link`，因为"慢"和"坏"是两件事。
- `degraded` 必须携带 `broken: string[]`（哪几条转发/会话），否则界面无法指路。

投影函数 `machineGroups(status)` 是纯函数，输入 `Status`，输出
`{ id, label, kind, link, broken, sessions }[]`。**排序规则不在这里**，它继续由
`orderSessions` 负责，两者正交。

### 2.4 视觉

不新增颜色。沿用现有 tokens：

| 含义 | token | 说明 |
|---|---|---|
| live | `--ok` | 与 `done` 同色系但不共用 badge，机器头用 6px 圆点 |
| degraded | `--warn` | 琥珀点，**无动画**——它不是"在努力"，是"部分坏了" |
| reconnecting | `--warn` | 琥珀，与 `blocked` 同色——**这正是问题**，见下 |
| offline | `--down` | 红 |
| 远端机器 | `--dim` 文本 + `--sunken` 底 | 机器头比会话卡轻一级 |

**冲突处理**：`reconnecting` 与 `blocked` 都用琥珀。解法是形状而非颜色——
`blocked` 是会话卡上的**实心 pill**，机器头是**一个 6px 圆点 + 旋转的环**。
颜色相同但位置与形状不同，且机器头永远在会话卡之外。若实测仍混淆，
`reconnecting` 改用 `--dim` + 动画环（不引入新色相）。`degraded` 用同一个点但
**不转**，于是"在重试"与"部分坏了"靠动画区分，不靠新颜色。

## 三、手机：独立信息架构

### 3.1 为什么不沿用桌面布局

桌面是"左栏舰队 + 右栏会话"的双栏。手机上一栏都放不下：`--fleet-width: 320px`
在 390pt 宽的机器上就没了主区。用户自己在 Codex-Android 里给出的答案是
**底部三个入口**（最近 / 项目 / 派发），这是经过真实使用的结论，照抄。

### 3.2 三层结构

```
┌──────────────────────────┐
│  ←  Fleet        ⌘ 状态条 │  ① 机器与连接状态（一行，可展开）
├──────────────────────────┤
│  ⚠ 2 need you            │  ② 需要你：置顶的注意力条
├──────────────────────────┤
│  sess-a        blocked   │
│  sess-b        working   │  ③ 会话列表（按全局排序）
│  ...                     │
├──────────────────────────┤
│  最近   项目   派发        │  ④ 底部三入口
└──────────────────────────┘
```

- **① 状态条**：一行，显示当前机器名 + 连接三态。点击展开成机器列表（切机器）。
  **永远只有一行**，不占版面。
- **② 注意力条**：只有 `attention > 0` 时出现，点击直接跳到最上面的 `blocked` 会话。
  这是整个手机界面**唯一允许用琥珀色大面积填充**的地方。
- **③ 会话列表**：与桌面同一套排序函数，同一套 badge。**不重排、不截断**。
- **④ 三入口**：最近（跨项目聚合）/ 项目（按目录分组）/ 派发（新建任务）。

### 3.3 会话详情：单列，动作收在底栏

```
┌──────────────────────────┐
│ ← sess-a    blocked  ⋯   │
├──────────────────────────┤
│  (日志 / diff，单列滚动)   │
│                          │
├──────────────────────────┤
│ [ Ask first ▾ ] [ 回答 ]  │  ⑤ 权限卡固定在底栏上方
└──────────────────────────┘
```

- 权限卡**不是浮层**，是底栏上方的固定条：手机上浮层会盖住上下文，
  而回答权限恰恰需要看上下文。
- `⋯` 菜单只放**允许的操作**（评论、取消回合、看用量）。**不放**推送、开 PR、
  丢弃变更、终端——理由见 `remote-access.md` 第六节，且是 daemon 侧拒绝，
  不是这里藏起来。
- 长按会话卡 = 多选（批量取消/已读），不做拖拽排序（触摸误触率高）。

### 3.4 手机专属的诚实规则

从用户自己的踩坑记录直接继承：

| 规则 | 来源 | UI 表现 |
|---|---|---|
| 半开连接不产生错误 | `RELAY_WATCHDOG.md` | 连接状态在 40s 内可能仍显示 `live`；**不显示"已断开"直到确定**，此时打 `stale` 标记（"正在确认"），`Link` 本身不变 |
| 写入不重试 | 同上 | 发送失败直接标红并保留草稿，**不自动重发**；重发是用户动作 |
| 后台定时器冻结 | 同上 | 回前台立即重建流（带 cursor），**不显示"已同步"直到第一帧到达** |
| 自动切换只在同机 | `sameMachine.ts` | 换机器必须显式确认；`unknown` 不自动切 |
| 指纹变了要拒绝 | `deviceTrust.ts` | 首次显示分组指纹；变化时红屏阻断，给出"重新配对" |

### 3.5 触控与可读性

- 最小触控目标 44×44（`--sp-*` 现有最大步长 20px，需要一条新规则，不是新 token）。
- 正文 `--fs-body: 14px` 在手机上偏小，手机侧用 15px 起；行高 1.5 不变。
- 会话卡在手机上**去掉 command 一行**（`--mono` 长命令会撑破卡片），
  改为在详情页显示。这是唯一"移动端隐藏信息"的地方，要在 PR 里注明。

## 四、配对流程（两屏）

```
屏 1（桌面）                      屏 2（手机）
┌────────────────────┐           ┌────────────────────┐
│ Connect a phone    │           │ Scan               │
│                    │           │                    │
│   ▓▓▓▓▓▓▓▓▓▓       │  ──扫──▶  │   [相机取景]        │
│   ▓ QR ▓▓▓▓▓       │           │                    │
│   ▓▓▓▓▓▓▓▓▓▓       │           │  或粘贴链接         │
│                    │           │                    │
│ 9F3A 7C21 B4E8 ... │           │  指纹 9F3A 7C21…    │
│ 10 分钟内有效       │           │  [ 信任并连接 ]      │
└────────────────────┘           └────────────────────┘
```

- 二维码**旁边必须有可手输的分组码**（相机权限被拒、屏幕坏、远程口头转述）。
- 桌面屏明确写有效期与"仅此一次"。
- 手机屏在连接前**显示将要 pin 的指纹**，让用户能核对——这是 `deviceTrust`
  的"首次要人"。
- 失败只有三种文案：`expired` / `already paired elsewhere` / `fingerprint changed`。
  **不给"未知错误"**。

## 五、动效与性能（沿用既有红线）

- 机器头进入：与卡片同一个 `card-in`，不新增 keyframes。
- 重连环：**只在 `reconnecting` 期间**转；进入 `live` 立即停。不用 CSS 无限动画，
  用一次性的 `transition` + 状态切换（避免"常驻动画循环"违反红线）。
- 手机上禁用卡片的 stagger 入场（列表长、触摸场景，入场延迟会让首屏变慢）。
  由 `prefers-reduced-motion` 之外的一条媒体查询控制，理由写进注释。
- 会话列表虚拟化**暂不做**：先量。50 条以内的真实舰队没有这个需要，
  提前做会引入滚动位置的持久化问题。

## 七、不做什么

- 不做主题切换（tokens 一次定死，见 FLOTILLA.md）。
- 不做 i18n（M2 起中文先行，现在不铺）。
- 不做平板专用布局（先按手机与桌面两端做好）。
- 不做会话列表虚拟化（先量再决定）。
- 不在手机上渲染终端（PTY 输入是桌面专属）。
